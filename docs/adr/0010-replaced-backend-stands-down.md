# 0010. 被顶替的后端主动退出，不再重连

- 状态：Accepted
- 日期：2026-10-13

## 背景

[ADR-0009](0009-credential-bound-backend-identity.md) 规定一张后端凭证就是一个后端，同一 backendId 多处连接时新连接顶替旧连接。网关原先顶替时直接 `terminate()` 旧连接：没有关闭码、没有任何消息。SDK 把它当成普通断线，约 1 秒后自动重连，重连又顶替了对方——两个共用同一张凭证的进程（例如同一服务的两个副本）会无限互踢，SDK 侧既不知道原因，也停不下来。

ADR-0009 之前这种情况只在两个进程填了完全相同的 instanceId 时出现，属于少见的配置错误；凭证绑定身份后，"共用一张凭证"本身就会触发，必须在协议层给出明确信号。

## 候选方案

1. **维持现状，只靠网关的 `backend.owner_flapping` 审计告警**：不改协议与 SDK，但互踢本身不停止，服务在告警期间持续不可用。
2. **旧连接胜出（拒绝新连接）**：天然不会互踢，但后端崩溃重启时旧连接往往尚未被判定断开，新进程要等到租约超时才能上线——与 ADR-0009 选择"新顶旧"的理由冲突。
3. **专用关闭码 + 被顶替方退出（选定）**：网关以专用关闭码关闭旧连接；SDK 收到后不再重连，状态变为 `closed`，`lastError`/`last_error` 记为 `REPLACED`。

## 决策

采用方案 3。

- 协议：新增关闭码 `GATEWAY_CLOSE_BACKEND_REPLACED = 4001`（`@zclaudia/gateway-protocol`、Python `zclaudia_gateway`），原因文本 `Backend replaced by a newer connection`。网关发出关闭帧后 2 秒内对方不完成关闭握手则强制断开（半死连接不会回应）。
- SDK（TS 与 Python）：控制连接以 4001 关闭时不重连，状态转为 `closed`；`lastError`/`last_error` 置为新增的 `REPLACED`（不是"失败的尝试"，而是退出原因，message 固定）。再次调用 `connect()`（Python 亦可 `start()`）即主动夺回身份，并按 ADR-0008 的生命周期清除该记录。
- 这扩充了 [ADR-0008](0008-python-backend-last-error.md) 的错误码集合；其余生命周期规则不变。
- SDK 自身断线重连时，新连接顶替的是自己那条已被弃用的旧 socket，旧 socket 上的事件本就被忽略，因此不会误判为被顶替。

## 后果

- 正面：共用凭证不再导致无限互踢，最新启动的实例稳定持有身份；应用能从 `lastError.code === 'REPLACED'` 得知原因（例如提示"该凭证已在别处使用"）。崩溃重启场景不受影响：新进程照常顶替旧进程的半死连接。
- 负面/需要承担的：被顶替的实例停止服务，需要运维介入（为每个实例签发独立凭证）；不认识 4001 的旧版 SDK 仍会重连互踢，只能靠网关审计告警发现，需升级 SDK。
- 触发重新评估的条件：出现同一逻辑后端需要多实例同时在线（多活）的需求——届时与 ADR-0009 一同重新设计实例维度。
